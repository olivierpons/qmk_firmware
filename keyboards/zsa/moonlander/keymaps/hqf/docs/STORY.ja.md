# 私がこのキーボードのために作ったすべて

私は Olivier Pons、開発者です。一日中コード、フランス語、英語、そして今は音声も入力しています。このキーマップはダウンロードしてきたレイアウトではなく、何ヶ月もかけたコミット一つひとつの積み重ねから生まれ、Linux 上で AZERTY を使う自分の仕事のやり方に完全に合わせたものです。このページはその全体像を語るものです。なぜ存在するのか、どうやってここまで来たのか。

## 問題点

AZERTY はタイプライター用に設計されたもので、プログラマー向けではありません。括弧や演算子は使いにくい組み合わせの奥に隠れていて、一日中フランス語とコードを行き来すると常に摩擦が生まれます。レイアウトと戦う代わりに、私はその周りにレイヤーを構築しました。

## 各レイヤーの役割

- **L0**:ベースの AZERTY。すでに手が覚えているものに近い状態。
- **L1**:プログラマーに必要なすべての記号を、ホームポジションを離れずに。
- **L2**:テンキーとフランス語のアクセント記号付き文字。
- **L3**:コピー/ペーストと OS 固有のショートカット。Linux、Windows、macOS は決して一致しないので。
- **L4/L5**:RGB ライティングとサウンド。見なくてもどのレイヤーにいるか分かる。
- **L6**:キーボードをゲームコントローラーに変える。

## 画面を起きたままにしておく

早い段階でマウスジグルのマクロを追加しました。長い通話や長い読書の間にマシンがロックしたりスリープしたりしないようにするためです。最初はカーソルが800ミリ秒ごとに少し動くだけでしたが、今は円を1ピクセルずつたどります。`M_JG_TOG` で開始・停止し、停止してもカーソルはその場に残ります。次に開始すると、同じ点から同じ設定で続きます。`M_JG_RUP` / `M_JG_RDN` で半径を拡大・縮小(デフォルトは10ピクセル、最小は1ピクセルで、それでもマウスは動きます)、`M_JG_DUP` / `M_JG_DDN` で2ピクセル間の休止を延長・短縮します(デフォルトは1秒、1ミリ秒まで短くでき、さらに速く、1ミリ秒あたり100ピクセルまで)。この4つのキーでは、文字を打つときのような短い押下で値が1変わり、押し続けると10ずつ、だんだん速く変わります。`M_JG_CTG` は、1周ごとに左クリックする位置を選びます。押すたびに8方向の次へ進み(北、北東、東、南東、南、南西、西、北西)、そのたびに少しずつ高くなる2回のビープ音が鳴り、最後に低いビープ音でクリックをオフにします。

## キーボードをコントローラーに変える

レイヤー6は完全にゲーム専用です:1つのキーでのタップダンスで切り替え、Rapid Fire マクロはキーやマウスボタンをタイマーで連打します。この間隔はキーボードそのものから、設定を再コンパイルすることなく、リアルタイムで速めたり遅めたりできます。

## 見なくても分かるフィードバック

レイヤーごとの RGB と、QMK のサウンドエフェクトのライブラリ——「カチッ」というタイピング音を含む——のおかげで、キーボードを見なくても自分がどのモードにいるか常に分かります。ちょっとしたことですが、「あれ、今どのレイヤーだっけ」という場面をかなり減らしてくれました。

## 意識しなくなったショートカット

ウィンドウマネージャーの組み合わせ(Ctrl+Alt+括弧、Ctrl+Alt+Z)、Linux、Windows、macOS のどれでも同じように動くコピー&ペースト、HTML タグの自動補完、一日に何十回も打つもののための署名マクロ——一つずつ、これらは考えなくてもいいことになっていきました。

## QMK に追随し続ける

QMK は時間とともに古い keycode を非推奨にします。`RGB_*` とマウスの keycode が `RM_*`/`MS_*` に置き換えられたとき、古い API の上で朽ちさせるのではなく、キーマップ全体を移行させました。

## 声を与える

最新のパーツ:Ctrl+Alt+K で、別途開発したオープンソースの音声入力ツール [opons-voxd](https://github.com/olivierpons/opons-voxd) を切り替えられます。これはこのキーボード上で、単にテキストを動かすだけでなく、「聞き始める」最初のキーです。

## なぜこれを共有するのか

誰もこれをそのままコピーすべきではありません——手も仕事の仕方も人それぞれです。ただ、記号のためのレイヤー、OS のショートカット、フィードバック、マクロ、そして今は音声というアイデアは、私がここに至るまでにかかった年月を誰かの分だけ節約できるかもしれません。完全なキーマップとビルド手順は一つ上のフォルダ、[キーマップの README](../README.md) にあります。
